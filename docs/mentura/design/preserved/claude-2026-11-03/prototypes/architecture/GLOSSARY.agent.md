# Glossary (agent-readable view)

Generated by `node glossary-query.ts agent` from the term records and usage.json. Do not edit by hand.

How to use: write with these labels exactly. Before using a word that looks like a term, `get` it; if its meaning is not what you mean, use the term named under Instead. A term with no usage note is not yet safe to use without reading its properties.

## account

A named party a venture keeps a record for, at accounts/<id>/account.json, with a relationship: client, customer, user, member, partner or other. Optional; who a product serves in general is its market

- id: `noun:account`, level: noun/venture, scope: venture, status: ontology new
- Must hold: standard CRM usage (Salesforce, HubSpot: account)
- Use for: (no usage note yet)

## agent harness

An AI harness in which the model directs its own steps and tool use in a loop toward a goal, acting on files, tools and systems between the person's turns, under permissions (Claude Code, Cursor, Codex, Hermes Agent). The default kind of interface. Every agent harness is an AI harness; a chatbot is not an agent harness

- id: `noun:agent-harness`, level: noun/interface, scope: venture, status: ontology new
- Must hold: standard agent harness (industry usage)
- Use for: (no usage note yet)

## agent-readable glossary

A glossary whose every entry also says how and when to use the term, so an agent (or a new person) can write with it correctly.

- id: `agent-glossary`, level: reference, scope: venture, status: proposed (sandbox)
- Must hold: E1 its entries are terms (words or phrases); E2 each entry says what its term means; GL1 limited to one subject field, work or venture; AG1 each entry says how and when to use the term
- Use for: the glossary view in which every entry also has a usage note; generated, never edited by hand
- Not for: a second copy of the glossary kept by hand
- Related: dictionary (is_a), glossary (is_a), index (overlap), registry (overlap), thesaurus (overlap)
