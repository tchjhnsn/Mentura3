# Outside host

**Moved, 2026-11-24.** This package came to `packages/platform/outside/` from tchjhnsn/mentura. The old console is retired, so where this page names `console/`, read it as the history of that console: the bridge it used is now `../bridge/`, and the business console in `web/` (`/studio`) takes its place. The thirteen function ids now come from Naive's `departments.json`, not the EE-090 decision text.

A venture's record store stays on Naive's connector registry. GitHub issues, projects, discussions, docs, reviews, actions, and repository files stay on `connectors/github.mjs`. This package is the host for a reading that store does not hold.

Nothing here registers a connector. Nothing here calls the term engine. A catalog row does not grant authority.

## What is built

`openToolHost` in `host.ts` keeps an append-only log. On the local console the log is a file under `<account workspace>/outside/<venture id>/events.jsonl`. A symlink or hard link at `outside`, at `events.jsonl`, or at the fixture outbox is refused before a write, and the same refusal applies to `knowledge` and `sources.json`. A caller error does not include file text. The fixture directory named by a connection is not followed when it is a symlink. An owner stamp that is a symlink is refused before the file is read. A receipt line that does not verify does not replace a receipt that did. That file is not a hosted store. Deleting a later line from it leaves the earlier signature, and the file cannot refuse that deletion. The hosted table opens only for a login with `select` and `insert` on `outside_log` and no other privilege: no role membership, no security-definer function outside the system catalogs, and no `session_replication_role` setting. Its triggers fire in replica mode. The authenticated login is `session_user`; a role default does not make `current_user` the principal. `sql/002-outside-account.sql` forces a row policy so that login sees and appends only the account inside the signed session assertion. The assertion key and the grant table are hidden from it. A grant lasts for one transaction and is removed after that transaction finishes. A hosted console, one whose `MENTURA_PUBLIC_ORIGIN` is `https`, opens the host through `openAccountOutsideHost` in `hosted-console.ts`. `console/lib/outside-host.ts` signs that session and passes the assertion. It does not take an account id from the browser. That path uses `outside_log` and does not fall back to the events file. `npm start` without that https origin keeps the file. The runtime does not create the table. The schema file is `sql/001-outside-log.sql`. The database must be distinct from the tenant record store and from the identity store. `console/lib/bridge.mjs` still reads the Naive workspace from the local console disk. That workspace is not this log. The docs site on Vercel has no console disk or database. The log is not `naive_records` and it is not a venture record. The only provider is `local-fixture`. Its catalog claim is `hypothesized`. The venture directory and the venture id must be the same folder inside the account. A policy decision about a different directory does not read this venture.

A write returns `awaiting-approval` and does not run the driver. A later `approve` submit checks the signer and the stamped account owner again, checks the held signature, and runs the driver once. That signature covers the authorization id, the connection id, the payload hash, the account, whether the hold is granted or revoked, and `expiresAt`. Changing or removing any of those on the log line makes the signature fail, and approve does not write the outbox. A connection line is signed the same way, including its fixture and lifecycle, and the signature covers the previous log line, so an appended fixture change or an older connection line does not redirect a write or restore a read. An inbound MAC covers the account, venture, connection, event id, and body. A MAC for one of those does not verify for another. The hold expires after 60 seconds. Revoke takes the authorization id from the hold, signs the revoked line, and a later approve does not run. An actor whose kind is not `person` is refused before any key file is opened. There is no agent proof and no HMAC for an agent. A function agent does not import this package. Agent use is not supported.

Secret files must be mode `0600`, owned by the process user, not symlinks, and outside the account workspace. The host zeros each key buffer after the call. Receipts store hashes. `accepted` is false. An inbound body with a bad HMAC is not appended.

`loadRequirement` checks the thirteen function ids named by EE-090. That check is not term admission. `outside/schemas/requirement.schema.json` is the record shape. `naiveRequirementCheck` in `naive-requirement.ts` asks Naive's `Validator` to accept that shape, and `openAccountOutsideHost` uses it. An id the schema rejects, or an extra field, does not bind. `outside/requirement-schema.test.ts` asks the same validator to accept a hypothesized record and reject a verified one. `openToolHost` refuses a bind unless `shapeCheck.accepted` returns true. A test may pass its own check. That test check is not `validate.mjs`.

## What is not built

Naive pin `a29321bde87cabb2ea18bc8162ef3163086e67a9` is fetched in CI with `NAIVE_READ_TOKEN` through `scripts/naive-git-auth.sh`. This environment does not have that token, and `gh` cannot see `tchjhnsn/naive`. `agents/outside-policy.ts` calls `refusedPerson` and `signers`. It loads only when the pin is installed. `outside/console-account.ts` opens the host on `<workspace>/.accounts/<Better Auth session user id>/`. That id is what pull request 275, at `88c04c0c5a95c22ea32e13c71827b20603225ef5`, passes to `ensureAccount` as `providerSubject`. The identity store's `personId` is a different value and does not select the directory. The session cookie is not read here and is not sent to the marketing site. Signup is on main. `console/lib/outside-host.ts` calls `requireIdentity().userId`, and `app/actions.ts` declares that submit as a server action. This package does not import the signup mail files.

No vendor is selected. The research CLI for that choice is not available. A real provider is a later catalog row with a hypothesized claim, after a person names a gap GitHub does not cover.
